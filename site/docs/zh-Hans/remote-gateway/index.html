把网关放在另一台机器上

Kiwano 由两半组成:网关(拥有数据库、路由 Agent 流量并计量的那个守护进程)与 客户端(管理它的桌面应用或 CLI)。默认两半在同一台电脑上,客户端通过数据库旁边的 socket 找到网关。

这一页讲的是另一种安排:网关在一台机器上,客户端在另一台。它针对的是"常开的那台不是 你正坐着的这台"这种形状 —— 家里的服务器、迷你主机、塞在柜子里的机器 —— 而你想在笔记本 上添加供应商、看用量、接管 Agent。

单机安装不需要这一页的任何东西。这里每个设置默认都没设,默认行为与以前完全一致。

两个平面,刻意分开

网关监听两个:

平面 上面走什么 客户端从哪儿够到它
管理面 供应商、路由、日志、配额、探测 —— app 与 CLI 读写的全部 /status 与每一个 /api/… 端点
数据面 你的 Agent 真正的请求与响应 你给 Agent 配置的那个 URL

两者分开配置,而这正是重点:它们走的东西不一样。管理面上走的是凭据(你存下的 key), 数据面上走的是请求本身 —— 你的 prompt 与回答,而且是明文,因为 Kiwano 不做 TLS (见下面的部署要求)。

在跑网关的那台机器上

给管理面一个监听地址,也给数据面一个:

KIWANO_ADMIN_ADDR=100.64.0.5:8318 \   # 管理:host:port
KIWANO_DATA_ADDR=100.64.0.5 \         # Agent 流量:是一个地址,不是 host:port
KIWANO_DATA_PORT=8317 \               # 可选,默认就是 8317
kiwanod
  • KIWANO_ADMIN_ADDR —— 不设就完全不监听 TCP:管理面是数据库旁边的 socket, 只有本机能到。
  • KIWANO_DATA_ADDR —— 不设就是 127.0.0.1:只有这台机器上的 Agent,别人的 进不来。它的值是一个 IP 地址,不是 host:port,因为端口有自己的变量 (KIWANO_DATA_PORT),一个数字两个来源就是它们对不上的开始。
  • 两者都会拒绝"谁都能连到"的地址(公网地址,或者 0.0.0.0)—— 除非你明说你就是要 —— 见两个开关。

在你用来管理的那台机器上

KIWANO_DAEMON_ADDR=100.64.0.5:8318 \
KIWANO_DAEMON_TOKEN=<网关的管理 token> \
kiwano status

同样这两个变量也能把桌面应用指向远端网关,但有一个实际前提:双击启动的 GUI 应用 不继承你 shell 的环境。要么从终端启动它,要么把变量放到 macOS 会读的地方 (启动前 launchctl setenv KIWANO_DAEMON_ADDR …,或在它的 Info.plist 里加一条 LSEnvironment)。

token 从哪儿来。 网关首次启动时铸一个,存在自己的库里。在网关那台机器上:

sqlite3 ~/.kiwano/kiwano.db \
  "select value from gateway_settings where key = 'gateway.admin_token'"

没有哪条命令会打印它;这个一行命令(或者 scp)就是路径。

关于这个 token 有两条规矩,都是刻意的:

  • 只有在命名了远端时才从环境变量读。 远端客户端绝不回落到自己那台机器上的 token 行 —— 那是另一个网关的行,把它发到别的主机上就是把凭据交给了错误的地方。
  • 地址写错是拒绝,不是回落。 KIWANO_DAEMON_ADDR 不是 host:port 时,命令报错 停下,而不是悄悄去连本机网关 —— 那会变成"客户端用了另一个 daemon,而你以为是你点名的 那个"。

两个开关

止步于你自己网络的地址 —— RFC1918(10.、192.168.、172.16.–172.31.)、loopback、 链路本地、以及 Tailscale 用的 100.64/10 —— 直接可用。谁都能连到的地址需要第二个变量:

KIWANO_ADMIN_ALLOW_ANY=1   # 管理面上走的是凭据
KIWANO_DATA_ALLOW_ANY=1    # 数据面上走的是你的 prompt 与回答

两者是分开的,一个不等于另一个。 一个决定让管理面面对网络的人,并没有因此决定让 流量面也面对 —— 那边漏出去的东西性质不同。这两个开关拦的正是那个一字之差 (0.0.0.0 写成 127.0.0.1)。

部署要求

跨机的传输是明文 + token。这是刻意决定而非疏漏,它带一条要求:

网关的这些监听不得暴露在你不控制的网络上。要跨这种网络,用 VPN —— Tailscale、 WireGuard,什么都行 —— 并把网关的 VPN 地址给这些变量。

理由是:自签证书不加验证等于没有;自签加钉指纹则不能轮换、每次重装都要重新配对。 两者都付出真实代价,防的却是威胁模型里不存在的对手 —— 你自己、在你自己的网络上。在这个 模型下,诚实的答案是私有网络加一个 token,而不是对着空气上密码学。

所以 100.64.0.5(tailnet 地址)正是这些变量为之设计的值。公网地址需要两个开关并且 一个过硬的理由。

端口

变量 默认 它命名什么
KIWANO_ADMIN_ADDR 不设(不监听 TCP) 管理面的 host:port
KIWANO_DATA_ADDR 127.0.0.1 数据面绑哪个接口
KIWANO_DATA_PORT 8317 数据面的端口
KIWANO_DAEMON_ADDR 不设(本机 socket) 客户端 → 网关管理面的 host:port
KIWANO_DAEMON_TOKEN 不设 客户端 → 那台网关的管理 token

客户端不需要被告知数据端口。/status 会报出网关数据面所在的地址与端口,接管时 写进 Agent 配置的就是那一对 —— 于是你笔记本上的 Agent 最终指向的是你服务器上的网关,而 不是它自己的 loopback。

验证一下

在你用来管理的那台机器上:

kiwano status

gateway: running 带着远端的版本号,说明管理面可达且认证通过。然后接管一个 Agent —— kiwano agents takeover claude —— 它会把那个 Agent 的配置改写成网关报出的地址,再发一个 请求。Agent 有回答,两个平面就都通了。

如果 daemon 明明在跑,kiwano status 却说网关不在,那是地址或 token 错了,不是网络:CLI 会说清楚它用不了的是哪一个。
