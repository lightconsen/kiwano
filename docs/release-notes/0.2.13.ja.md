### 追加

- **daemon を別のマシンに置けます。** クライアントは、自分が動いているマシンではない
  ゲートウェイを指せるようになりました — アドレスは `KIWANO_DAEMON_ADDR`、管理面の
  トークンは `KIWANO_DAEMON_TOKEN` — app と CLI の行うことはすべてこの接続を通ります。
  そのために管理面に平文 TCP の形態が加わり（デプロイ要件は下記）、データ面は agent が
  向くべきポートを報告します。つまり 2 台目のマシンから実行したテイクオーバーは、自分
  の loopback ではなく**あちら側**のアドレスを設定に書きます。

- **クライアントが自分のデータベースを持ちます。** `kiwano.db` の隣に `local.db` が
  増え、**このマシン**についてのみ成り立つもの — 検出器が見つけられない agent に宣言
  したディレクトリ、どの agent にルールを注入したかの印、テイクオーバーを取り消すため
  のバックアップ — を保持します。初回起動時にこれらは共有ファイルから一度だけ取り込
  まれます。冪等で、**元は削除しません**（ダウングレードしても読めます）。

### 変更

- **このバージョンから Kiwano は Apache-2.0 です。** 0.1.6 から GPL-3.0-or-later
  でした。寛容なライセンスは再利用者から copyleft の義務を外し、明示的な特許許諾は
  残します — MIT との違いとして知っておく価値のある 2 点です。0.2.12 以前は
  GPL-3.0-or-later のままです。すでにリリース済みで、与えた許諾は取り消せないため、
  線引きはファイルではなくバージョンによります。

- **app と CLI は daemon のクライアントになりました。** 読み書きはすべて管理面の API
  を通り、共有データベースに書き込むのは daemon だけです。画面は変わりません。変わる
  のは各行の持ち主で、上の「別のマシン」はそれによって初めて成り立ちます。

- **ゲートウェイが動いていないとき、`kiwano status` はそう告げて止まります。** 以前は
  ローカルのデータベースを読んで、provider・バインディング・使用行の件数を出していま
  した。しかし自分のデータベースから答えるクライアントは、別のマシンを指した瞬間に
  別のマシンについて答えています。要約は削除し、2 つの状態を区別する手段は終了コード
  1 のままです。

- **`kiwano providers edit` は指定したフィールドだけを送ります。** provider の名前を
  変えても、その上限・バインディング・詳細設定をまとめて送り直すことはなくなりました。

### 削除

- **`kiwano reload`、グローバルフラグ `--no-reload`、管理面の `POST /reload`。** 書き
  込みのルートはそれぞれ自分でルート表を読み直します — バインディングを書いたプロセス
  が、それでルーティングするプロセスです — このコマンドに尋ねることは残っていません
  でした。スクリプト内の呼び出しは削除できます。

### 修正

- **プロバイダー画面は、各社が禁じていることを約束しなくなりました。** 公式プランで
  サインイン済みの Agent の隣でプロバイダーを追加しようとすると、以前は公式 OAuth は
  「まだプロキシできません」と表示されていました — その「まだ」は、いずれ対応する
  予定のように読めます。しかしそうではありません。Anthropic の規約（2026 年 2 月）は
  Free・Pro・Max のログイン情報を Claude 自身のアプリに限定し、利用者の代わりに
  リクエストをルーティングすることを認められない行為として明記しています。いま
  表示されるのはその理由と、開かれている道 — API キーでプロバイダーを追加する方法です。

- **`kiwano providers edit` は provider の既定モデルを消さなくなりました。** この
  コマンドに対応するフラグはなく、組み立て直した行は常に空を送っていました — つまり
  どのフィールドの編集でも、黙って消えていました。
