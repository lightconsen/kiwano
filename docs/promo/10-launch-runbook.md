# 10 — 完整推广执行步骤(runbook)

用法:**从上往下按时间做**,每一步都写了「做什么 / 用哪份材料 / 坑 / 完成判据」。  
材料本身在 `01`~`09`,本文件不重复内容,只负责把它们在正确的时间点用出去。

时间基准:**今天 2026-09-20(周日)**。HN 的黄金窗口是**周二~周四 UTC 14:00–17:00  
= 北京 22:00–次日 01:00**,所以主爆点定在 **9/24(周四)22:00 北京时间**。

## 阶段 3 · 9/24(周四)22:00 —— Show HN + X,主爆点

### 发布前 60 分钟

- 22:00 是 UTC 14:00,美东刚上班,欧洲在下午——HN 一天里最好的落点。
- 再核一次:`catalog.json` 的 `total`(现在 24)、版本号(现在 v0.1.16)、下载链、视频链。
- 把 `02-show-hn.md` 的正文复制到纯文本编辑器,**清掉所有反引号**(HN 会原样显示反引号字符)。

### 发布动作

| 时间    | 动作                               | 材料   |
| ----- | -------------------------------- | ---- |
| 22:00 | 发 Show HN,标题用第 1 条(73 字符,已实测不超限) | `02` |
| 22:05 | X 发 Post 1(带视频链接),之后每隔几小时续一条     | `04` |

### 前 2 小时的纪律(决定成败)

- **守在评论区,每条都回**,语气谦逊、给具体选择而不是辩解。
- **预答对比题**:cc-switch / LiteLLM / claude-code-router —— 口径在 `01-pitch.md` FAQ,别临场编。
- 有人质疑信任就跑一次 `gh attestation verify` 贴结果,**这招比文字有说服力**。
- **2 小时内别改标题**(改标题会重新计分)。

### 失败预案

| 情况               | 处理                                                           |
| ---------------- | ------------------------------------------------------------ |
| 帖子没上首页           | 正常,大多数 Show HN 都上不去。**不要删帖重发**(重发会被判 spam);等次日再发 Reddit,长尾照走 |
| 出现"这和 xx 有什么区别"  | 用 `01` 的对比表答,姿态是"往前走一步",不踩对手                                 |
| 有人指出 Windows 未签名 | 直接承认"known gap, on the list",别绕                              |

## 阶段 6 · 之后 4~6 周 —— 长尾与节奏

- **每个小版本(0.1.17 起)挑一个亮点单独发一帖** —— 你的 CHANGELOG 写得讲究,  
  每版的告警/策略/接管能力都能单拎出来成话题。
- **周日晚汇总**:R2 下载数、star、首个外部 issue。别只盯 star,下载数和外部 issue  
  才是真实信号。
- **Product Hunt / AlternativeTo 可选**:与 Show HN 错开至少一周,别同时抽干注意力(`09` D 节)。
- **找更多列表**:GitHub 搜 `topic:awesome-list` + 关键词(`09` E 节);先读 CONTRIBUTING,  
  确认年龄/star 门槛、一次能提几条、PR 还是 issue 表单——这三样决定过还是被机器人关掉。
