### 新增

- **可以把 daemon 放在另一台机器上。** 客户端现在可以指向一台不在本机的网关 ——
  `KIWANO_DAEMON_ADDR` 给地址、`KIWANO_DAEMON_TOKEN` 给它的管理面凭据 —— app 与 CLI
  做的事都经这条连接。管理面为此加了明文 TCP 形态（部署要求见下），数据面会报出 agent
  该指向的端口：于是在第二台机器上发起的接管，写进配置的是**那一台**的地址，而不是它
  自己的 loopback。

- **客户端有了自己的库。** `kiwano.db` 旁边多一个 `local.db`，装的是只对**这台机器**
  成立的东西：你为探测器找不到的 agent 声明过的目录、哪些 agent 注入过规则、以及接管
  可以撤销所依赖的备份。首次启动时这些行从共享文件里搬一次 —— 一次性、幂等，并且
  **不删原件**，降级回去仍能读到。

### 变更

- **从这一版起，Kiwano 是 Apache-2.0。** 0.1.6 起一直是 GPL-3.0-or-later。换成宽松
  许可是去掉复用者的 copyleft 义务，同时保留明确的专利授权 —— 这是它与 MIT 值得知道的
  两点差别。0.2.12 及更早的版本仍是 GPL-3.0-or-later：那些已经发布，已授出的许可收不
  回来，所以分界按版本而不是按文件。

- **app 与 CLI 都成了 daemon 的客户端。** 读写都走它的管理面 API，共享库的唯一写入者
  是 daemon。界面不变；变的是每一行归谁 —— 也正因为这样，上面那台"另一台机器"才成立。

- **网关不在时，`kiwano status` 只报状态、然后停下。** 它原本会读本机库，报出配了多少
  provider、绑定和用量行。可一个从自己库里作答的客户端，在被指向另一台机器的那一刻答
  的就是另一台 —— 所以那份摘要没了；区分两种状态的仍然是退出码 1。

- **`kiwano providers edit` 只发你点名的字段。** 改一个 provider 的名字，不会再顺手把
  它的限额、绑定和高级设置整份重发一遍。

### 移除

- **`kiwano reload`、全局标志 `--no-reload`、以及管理面的 `POST /reload`。** 每条写
  路由现在自己重读路由表 —— 写下绑定的是哪个进程，按它路由的就是哪个进程 —— 那条命令
  已经没有要问的事了。脚本里的调用可以直接删掉。

### 修复

- **Provider 页面不再承诺厂商禁止的事。** 在已用官方套餐登录的 Agent 旁边添加
  Provider 时，界面原本写着官方 OAuth「目前无法代理」—— 这个「目前」读起来像一件
  待办。它不是待办：Anthropic 的条款（2026 年 2 月）把 Free、Pro、Max 的凭据限制在
  Claude 自家应用内，并明确把「代用户路由请求」列为不允许的事。现在那句话直接说明
  原因，并指向仍然通畅的那条路 —— 用 API Key 添加 Provider。

- **`kiwano providers edit` 不再清掉 provider 的默认模型。** 这条命令没有对应的标志，
  而它重建的那一行总是发一个空的进去 —— 于是任何一次编辑、改任何字段，都会把它悄悄
  抹掉。
