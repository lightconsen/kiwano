# 把閘道放在另一台機器上

Kiwano 由兩半組成:**閘道**(擁有資料庫、路由 Agent 流量並計量的那個守護行程)與
**用戶端**(管理它的桌面應用程式或 CLI)。預設兩半在同一台電腦上,用戶端透過資料庫旁邊
的 socket 找到閘道。

這一頁講的是另一種安排:閘道在一台機器上,用戶端在另一台。它針對的是「常開的那台不是
你正坐著的這台」這種形狀 —— 家裡的伺服器、迷你主機、塞在櫃子裡的機器 —— 而你想在筆電
上新增供應商、看用量、接管 Agent。

單機安裝不需要這一頁的任何東西。這裡每個設定預設都沒設,預設行為與以前完全一致。

## 兩個平面,刻意分開

閘道監聽兩個:

| 平面 | 上面走什麼 | 用戶端從哪兒夠到它 |
|---|---|---|
| **管理面** | 供應商、路由、日誌、配額、探測 —— app 與 CLI 讀寫的全部 | `/status` 與每一個 `/api/…` 端點 |
| **資料面** | 你的 Agent 真正的請求與回應 | 你給 Agent 設定的那個 URL |

兩者分開設定,而這正是重點:它們走的東西不一樣。管理面上走的是**憑證**(你存下的 key),
資料面上走的是**請求本身** —— 你的 prompt 與回答,而且是明文,因為 **Kiwano 不做 TLS**
(見下面的[部署要求](#部署要求))。

## 在跑閘道的那台機器上

給管理面一個監聽位址,也給資料面一個:

```sh
KIWANO_ADMIN_ADDR=100.64.0.5:8318 \   # 管理:host:port
KIWANO_DATA_ADDR=100.64.0.5 \         # Agent 流量:是一個位址,不是 host:port
KIWANO_DATA_PORT=8317 \               # 可選,預設就是 8317
kiwanod
```

- **`KIWANO_ADMIN_ADDR`** —— 不設就完全不監聽 TCP:管理面是資料庫旁邊的 socket,
  只有本機能到。
- **`KIWANO_DATA_ADDR`** —— 不設就是 `127.0.0.1`:只有這台機器上的 Agent,別人的
  進不來。它的值是**一個 IP 位址,不是 `host:port`**,因為埠有自己的變數
  ([`KIWANO_DATA_PORT`](#埠)),一個數字兩個來源就是它們對不上的開始。
- 兩者都會拒絕「誰都能連到」的位址(公網位址,或者 `0.0.0.0`)—— 除非你明說你就是要 ——
  見[兩個開關](#兩個開關)。

## 在你用來管理的那台機器上

```sh
KIWANO_DAEMON_ADDR=100.64.0.5:8318 \
KIWANO_DAEMON_TOKEN=<閘道的管理 token> \
kiwano status
```

同樣這兩個變數也能把**桌面應用程式**指向遠端閘道,但有一個實際前提:雙擊啟動的 GUI
應用程式**不繼承**你 shell 的環境。要麼從終端啟動它,要麼把變數放到 macOS 會讀的地方
(啟動前 `launchctl setenv KIWANO_DAEMON_ADDR …`,或在它的 `Info.plist` 裡加一條
`LSEnvironment`)。

**token 從哪兒來。** 閘道首次啟動時鑄一個,存在自己的庫裡。在閘道那台機器上:

```sh
sqlite3 ~/.kiwano/kiwano.db \
  "select value from gateway_settings where key = 'gateway.admin_token'"
```

沒有哪條命令會印它;這個一行命令(或者 `scp`)就是路徑。

關於這個 token 有兩條規矩,都是刻意的:

- **只有在命名了遠端時才從環境變數讀。** 遠端用戶端絕不回落到**自己**那台機器上的
  token 列 —— 那是另一個閘道的列,把它送到別的主機上就是把憑證交給了錯誤的地方。
- **位址寫錯是拒絕,不是回落。** `KIWANO_DAEMON_ADDR` 不是 `host:port` 時,命令報錯
  停下,而不是悄悄去連本機閘道 —— 那會變成「用戶端用了另一個 daemon,而你以為是你點名
  的那個」。

## 兩個開關

止步於你自己網路的位址 —— RFC1918(`10.`、`192.168.`、`172.16.`–`172.31.`)、loopback、
連結本地、以及 Tailscale 用的 `100.64/10` —— 直接可用。誰都能連到的位址需要第二個變數:

```sh
KIWANO_ADMIN_ALLOW_ANY=1   # 管理面上走的是憑證
KIWANO_DATA_ALLOW_ANY=1    # 資料面上走的是你的 prompt 與回答
```

**兩者是分開的,一個不等於另一個。** 一個決定讓管理面面對網路的人,並沒有因此決定讓
流量面也面對 —— 那邊漏出去的東西性質不同。這兩個開關攔的正是那個一字之差
(`0.0.0.0` 寫成 `127.0.0.1`)。

## 部署要求

跨機的傳輸是**明文 + token**。這是刻意決定而非疏漏,它帶一條要求:

> 閘道的這些監聽**不得暴露在你不控制的網路上**。要跨這種網路,用 VPN —— Tailscale、
> WireGuard,什麼都行 —— 並把閘道的 VPN 位址給這些變數。

理由是:自簽憑證**不加驗證等於沒有**;自簽**加釘指紋**則不能輪換、每次重裝都要重新配對。
兩者都付出真實代價,防的卻是威脅模型裡不存在的對手 —— 你自己、在你自己的網路上。在這個
模型下,誠實的答案是私有網路加一個 token,而不是對著空氣上密碼學。

所以 `100.64.0.5`(tailnet 位址)正是這些變數為之設計的值。公網位址需要兩個開關**並且**
一個過硬的理由。

## 埠

| 變數 | 預設 | 它命名什麼 |
|---|---|---|
| `KIWANO_ADMIN_ADDR` | 不設(不監聽 TCP) | 管理面的 `host:port` |
| `KIWANO_DATA_ADDR` | `127.0.0.1` | 資料面綁哪個介面 |
| `KIWANO_DATA_PORT` | `8317` | 資料面的埠 |
| `KIWANO_DAEMON_ADDR` | 不設(本機 socket) | 用戶端 → 閘道管理面的 `host:port` |
| `KIWANO_DAEMON_TOKEN` | 不設 | 用戶端 → 那台閘道的管理 token |

用戶端**不需要**被告知資料埠。`/status` 會報出閘道資料面所在的**位址與埠**,接管時
寫進 Agent 設定的就是那一對 —— 於是你筆電上的 Agent 最終指向的是你伺服器上的閘道,而
不是它自己的 loopback。

## 驗證一下

在你用來管理的那台機器上:

```sh
kiwano status
```

`gateway: running` 帶著遠端的版本號,說明管理面可達且認證通過。然後接管一個 Agent ——
`kiwano agents takeover claude` —— 它會把那個 Agent 的設定改寫成閘道報出的位址,再發一個
請求。Agent 有回答,兩個平面就都通了。

如果 daemon 明明在跑,`kiwano status` 卻說閘道不在,那是位址或 token 錯了,不是網路:CLI
會說清楚它用不了的是哪一個。
