# ゲートウェイを別のマシンに置く

Kiwano は二つの半分でできています。**ゲートウェイ**(データベースを所有し、エージェントの
トラフィックをルーティングして計量するデーモン)と、それを管理する**クライアント**
(デスクトップアプリまたは CLI)です。既定では両方は同じコンピューター上にあり、クライアント
はデータベースの隣のソケットを通してゲートウェイに到達します。

このページはもう一方の配置についてです。ゲートウェイが一方のマシン、クライアントが別の
マシン。「いつも起きているマシンが、自分が今座っているマシンではない」という形 —— 自宅
サーバー、ミニ PC、戸棚の中の箱 —— のためにあり、ノート PC からプロバイダーを追加し、
使用量を見て、エージェントをテイクオーバーしたいときのものです。

単一マシンのインストールにこのページの内容は一切必要ありません。ここにある設定はすべて
既定で未設定で、既定の挙動はこれまでとまったく同じです。

## 二つのプレーンは、意図的に別です

ゲートウェイは二つをリッスンします。

| プレーン | 何が流れるか | クライアントはどこから届くか |
|---|---|---|
| **管理プレーン** | プロバイダー、ルート、ログ、クォータ、プローブ —— app と CLI が読み書きするすべて | `/status` とすべての `/api/…` エンドポイント |
| **データプレーン** | エージェントの実際のリクエストとレスポンス | エージェントに設定された URL |

別々に設定します。それが要点です。流れるものが違うからです。管理プレーンを流れるのは
**資格情報**(保存したキー)。データプレーンを流れるのは**リクエストそのもの** —— あなたの
プロンプトと回答で、しかも平文です。**Kiwano は TLS を行いません**(下記の
[デプロイ要件](#デプロイ要件)を参照)。

## ゲートウェイを動かすマシンで

管理プレーンにリッスンするアドレスを、データプレーンにも一つ与えます。

```sh
KIWANO_ADMIN_ADDR=100.64.0.5:8318 \   # 管理:host:port
KIWANO_DATA_ADDR=100.64.0.5 \         # エージェントのトラフィック:アドレスであり host:port ではない
KIWANO_DATA_PORT=8317 \               # 任意。既定は 8317
kiwanod
```

- **`KIWANO_ADMIN_ADDR`** —— 未設定なら TCP リスナーはまったく立ちません。管理プレーンは
  データベースの隣のソケットで、このマシンからしか届きません。
- **`KIWANO_DATA_ADDR`** —— 未設定なら `127.0.0.1`。このマシン上のエージェントだけで、
  他人のものは入りません。値は **IP アドレスであり `host:port` ではありません**。ポートには
  専用の変数([`KIWANO_DATA_PORT`](#ポート))があり、一つの数字に二つの出所があることが、
  それらが食い違う始まりだからです。
- どちらも「どこからでも到達できる」アドレス(公開アドレス、または `0.0.0.0`)を、そう
  意図していると明示しない限り拒否します —— [二つのスイッチ](#二つのスイッチ)を参照。

## 管理する側のマシンで

```sh
KIWANO_DAEMON_ADDR=100.64.0.5:8318 \
KIWANO_DAEMON_TOKEN=<ゲートウェイの管理トークン> \
kiwano status
```

同じ二つの変数で**デスクトップアプリ**も遠隔のゲートウェイに向けられますが、実際上の
注意が一つあります。ダブルクリックで起動した GUI アプリは、あなたのシェルの環境を
**継承しません**。ターミナルから起動するか、macOS が読む場所に置いてください
(起動前に `launchctl setenv KIWANO_DAEMON_ADDR …`、または `Info.plist` に
`LSEnvironment` の項目)。

**トークンはどこから来るか。** ゲートウェイが初回起動時に鋳造し、自分のデータベースに
保管します。ゲートウェイのマシンで:

```sh
sqlite3 ~/.kiwano/kiwano.db \
  "select value from gateway_settings where key = 'gateway.admin_token'"
```

これを表示するコマンドはありません。この一行(または `scp`)がその経路です。

このトークンについて二つの規則があり、どちらも意図的です。

- **遠隔を名指ししたときにだけ、環境変数から読みます。** 遠隔クライアントは**自分**の
  マシンのトークン行にフォールバックしません —— その行は別のゲートウェイのもので、
  それを別のホストへ送るのは、資格情報を間違った場所に渡すことです。
- **書式の違うアドレスは拒否で、フォールバックではありません。** `KIWANO_DAEMON_ADDR` が
  `host:port` でなければ、コマンドはエラーで止まります。黙ってローカルのゲートウェイと
  話すことはしません —— それは「名指ししたのとは別のデーモンを、クライアントが黙って
  使った」ということだからです。

## 二つのスイッチ

自分のネットワークで止まるアドレス —— RFC1918(`10.`、`192.168.`、`172.16.`–`172.31.`)、
loopback、リンクローカル、Tailscale が使う `100.64/10` —— はそのまま使えます。どこからでも
到達できるアドレスには二つ目の変数が要ります。

```sh
KIWANO_ADMIN_ALLOW_ANY=1   # 管理プレーンを流れるのは資格情報
KIWANO_DATA_ALLOW_ANY=1    # データプレーンを流れるのはプロンプトと回答
```

**両者は別で、一方が他方を意味しません。** 管理プレーンをネットワークに晒すと決めた人が、
それによってトラフィックのプレーンも晒すと決めたことにはなりません —— 漏れるものの性質が
違うからです。この二つのスイッチが捕まえるのは、あの一文字の間違い(`127.0.0.1` を
`0.0.0.0` と書く)です。

## デプロイ要件

マシンをまたぐ転送は**平文 + トークン**です。これは省略ではなく意図的な決定で、一つの要件を
伴います。

> ゲートウェイのこれらのリスナーは、**あなたが制御しないネットワークに晒してはいけません**。
> またぐ必要があるなら VPN を使ってください —— Tailscale、WireGuard、何でも —— そして
> ゲートウェイの VPN アドレスをこれらの変数に与えてください。

理由: 検証されない自己署名証明書は暗号化ではありません。ピン留めする自己署名証明書は
ローテーションできず、再インストールのたびに再ペアリングが要ります。どちらも実際の代償を
払い、脅威モデルに存在しない相手 —— 自分自身、自分のネットワーク上の —— に対する防御を
買います。このモデルでは、正直な答えはプライベートネットワークとトークンであり、誰も
いない相手に向けた暗号技術ではありません。

つまり `100.64.0.5`(tailnet のアドレス)が、これらの変数が想定している値です。公開
アドレスには二つのスイッチ**と**、それに見合う理由が要ります。

## ポート

| 変数 | 既定 | 何を名指しするか |
|---|---|---|
| `KIWANO_ADMIN_ADDR` | 未設定(TCP リスナーなし) | 管理プレーンの `host:port` |
| `KIWANO_DATA_ADDR` | `127.0.0.1` | データプレーンが束縛するインターフェース |
| `KIWANO_DATA_PORT` | `8317` | データプレーンのポート |
| `KIWANO_DAEMON_ADDR` | 未設定(ローカルソケット) | クライアント → ゲートウェイ管理プレーンの `host:port` |
| `KIWANO_DAEMON_TOKEN` | 未設定 | クライアント → そのゲートウェイの管理トークン |

クライアントはデータポートを**知らされる必要がありません**。`/status` がゲートウェイの
データプレーンがある**アドレスとポート**を報告し、テイクオーバーはその組をエージェントの
設定に書き込みます —— こうしてノート PC 上のエージェントは、自分の loopback ではなく
サーバー上のゲートウェイを指すことになります。

## 確認する

管理する側のマシンで:

```sh
kiwano status
```

`gateway: running` と遠隔のバージョンが出れば、管理プレーンに到達し認証も通っています。
次にエージェントを一つテイクオーバーします —— `kiwano agents takeover claude` ——
ゲートウェイが報告したアドレスにそのエージェントの設定が書き換わり、リクエストを送ります。
エージェントが答えたら、両方のプレーンが動いています。

デーモンが動いているのに `kiwano status` がゲートウェイ不在と言うなら、それはアドレスか
トークンの誤りで、ネットワークではありません。CLI はどちらを使えなかったかを言います。
