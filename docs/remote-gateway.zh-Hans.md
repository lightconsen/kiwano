# 把网关放在另一台机器上

Kiwano 由两半组成:**网关**(拥有数据库、路由 Agent 流量并计量的那个守护进程)与
**客户端**(管理它的桌面应用或 CLI)。默认两半在同一台电脑上,客户端通过数据库旁边的
socket 找到网关。

这一页讲的是另一种安排:网关在一台机器上,客户端在另一台。它针对的是"常开的那台不是
你正坐着的这台"这种形状 —— 家里的服务器、迷你主机、塞在柜子里的机器 —— 而你想在笔记本
上添加供应商、看用量、接管 Agent。

单机安装不需要这一页的任何东西。这里每个设置默认都没设,默认行为与以前完全一致。

## 两个平面,刻意分开

网关监听两个:

| 平面 | 上面走什么 | 客户端从哪儿够到它 |
|---|---|---|
| **管理面** | 供应商、路由、日志、配额、探测 —— app 与 CLI 读写的全部 | `/status` 与每一个 `/api/…` 端点 |
| **数据面** | 你的 Agent 真正的请求与响应 | 你给 Agent 配置的那个 URL |

两者分开配置,而这正是重点:它们走的东西不一样。管理面上走的是**凭据**(你存下的 key),
数据面上走的是**请求本身** —— 你的 prompt 与回答,而且是明文,因为 **Kiwano 不做 TLS**
(见下面的[部署要求](#部署要求))。

每个平面也有**自己的凭据**,两者并不是同一个:

| 平面 | 出示什么 | 几个 |
|---|---|---|
| 管理面 | `KIWANO_DAEMON_TOKEN` —— 网关的管理 token | 每个网关一个,给操作者 |
| 数据面 | 一把**客户端密钥**(`kw-ag-…`),每个 Agent 一个 | 每个 Agent 一个,想要的话每个 Agent 可以更多 |

管理 token 是给一个操作者的一个秘密。客户端密钥是 Agent 配置携带的东西,它是*为*那个
Agent 铸的,而且可以被设限:能花多少、能点名哪些模型、能用哪些供应商。那就是下面那一节,
也正是为什么一把泄露的客户端密钥是有边界的,而泄露的管理 token 不是。

## 在跑网关的那台机器上

给管理面一个监听地址,也给数据面一个:

```sh
KIWANO_ADMIN_ADDR=100.64.0.5:8318 \   # 管理:host:port
KIWANO_DATA_ADDR=100.64.0.5 \         # Agent 流量:是一个地址,不是 host:port
KIWANO_DATA_PORT=8317 \               # 可选,默认就是 8317
kiwanod
```

- **`KIWANO_ADMIN_ADDR`** —— 不设就完全不监听 TCP:管理面是数据库旁边的 socket,
  只有本机能到。
- **`KIWANO_DATA_ADDR`** —— 不设就是 `127.0.0.1`:只有这台机器上的 Agent,别人的
  进不来。它的值是**一个 IP 地址,不是 `host:port`**,因为端口有自己的变量
  ([`KIWANO_DATA_PORT`](#端口)),一个数字两个来源就是它们对不上的开始。
- 两者都会拒绝"谁都能连到"的地址(公网地址,或者 `0.0.0.0`)—— 除非你明说你就是要 ——
  见[两个开关](#两个开关)。

## 在你用来管理的那台机器上

```sh
KIWANO_DAEMON_ADDR=100.64.0.5:8318 \
KIWANO_DAEMON_TOKEN=<网关的管理 token> \
kiwano status
```

同样这两个变量也能把**桌面应用**指向远端网关,但有一个实际前提:双击启动的 GUI 应用
**不继承**你 shell 的环境。要么从终端启动它,要么把变量放到 macOS 会读的地方
(启动前 `launchctl setenv KIWANO_DAEMON_ADDR …`,或在它的 `Info.plist` 里加一条
`LSEnvironment`)。

**token 从哪儿来。** 网关首次启动时铸一个,存在自己的库里。在网关那台机器上:

```sh
sqlite3 ~/.kiwano/kiwano.db \
  "select value from gateway_settings where key = 'gateway.admin_token'"
```

没有哪条命令会打印它;这个一行命令(或者 `scp`)就是路径。

关于这个 token 有两条规矩,都是刻意的:

- **只有在命名了远端时才从环境变量读。** 远端客户端绝不回落到**自己**那台机器上的
  token 行 —— 那是另一个网关的行,把它发到别的主机上就是把凭据交给了错误的地方。
- **地址写错是拒绝,不是回落。** `KIWANO_DAEMON_ADDR` 不是 `host:port` 时,命令报错
  停下,而不是悄悄去连本机网关 —— 那会变成"客户端用了另一个 daemon,而你以为是你点名的
  那个"。

## 客户端密钥能做什么

密钥就是数据面的凭据。它命名一个 Agent(路由需要的就是这个),并且可以带三条限制,全部
在**请求到达供应商之前**检查:

```sh
kiwano clients list                                  # 句柄、Agent、各自能做什么
kiwano clients add --agent claude --label "laptop"   # 密钥只打印一次
kiwano clients limits ck-1a2b3c4d --window day:200:requests --window monthly:20:USD
kiwano clients policy ck-1a2b3c4d --model claude-sonnet-4-5 --provider p-work
kiwano clients rotate ck-1a2b3c4d                    # 新密钥,同一句柄与预算
```

- **花费窗口** —— `day` / `weekly` / `monthly` / `yearly` / `all`,单位是 `requests`、
  `wan_tokens`(万 tokens)或某种货币。量的是 Agent 的限额所用的同一套本地日历边界。超出
  任何一个窗口:**429**,并带一个 `Retry-After` 说明它还剩多少。
- **模型** —— 只允许列出的模型 id,大小写不敏感地匹配。结尾的 `*` 让一个条目变成**族**:
  `claude-haiku-*` 允许所有 id 以 `claude-haiku-` 开头的模型,包括你写下这份清单之后才发布
  的 —— 这就是规则与一份会过期的清单之间的差别。这是**唯一**的通配形态:出现在别处的 `*`
  会在写入时被拒,因为一个看起来像通配、却什么都匹配不到的条目,就是一把悄悄拒绝所有模型
  的密钥。落在清单外的模型:**403**,消息会点名那条规则。在清单生效时读不出模型的请求同样
  被拒,因为无法检查的允许不算允许。
- **供应商** —— 只允许列出的供应商 id。一把不被允许使用该 Agent 主供应商的密钥,会被路由
  到一个它可用的(多供应商策略),或者在策略是 `single` 时被拒(403) —— "就这一个供应商,
  不故障转移"不是一把密钥能靠升级自己绕开的话。

同一个 Agent 的两把密钥就是两个客户端、两份预算,这正是重点:一台笔记本和一台台式机在跑
同一个 Agent,可以分别设限。轮换密钥保留句柄、策略与已记录的用量,所以它不是清空限额的
办法。

密钥本身的存放方式与供应商的密钥一样 —— 明文,因为它在 Agent 的配置里也是明文 —— 并且
和其余每一个凭据一样,会从捕获的请求体里被清除。管理界面从不打印已存的密钥:只有 `add`
与 `rotate` 在铸它时显示一次。

## 两个开关

止步于你自己网络的地址 —— RFC1918(`10.`、`192.168.`、`172.16.`–`172.31.`)、loopback、
链路本地、以及 Tailscale 用的 `100.64/10` —— 直接可用。谁都能连到的地址需要第二个变量:

```sh
KIWANO_ADMIN_ALLOW_ANY=1   # 管理面上走的是凭据
KIWANO_DATA_ALLOW_ANY=1    # 数据面上走的是你的 prompt 与回答
```

**两者是分开的,一个不等于另一个。** 一个决定让管理面面对网络的人,并没有因此决定让
流量面也面对 —— 那边漏出去的东西性质不同。这两个开关拦的正是那个一字之差
(`0.0.0.0` 写成 `127.0.0.1`)。

## 部署要求

跨机的传输是**明文 + token**。这是刻意决定而非疏漏,它带一条要求:

> 网关的这些监听**不得暴露在你不控制的网络上**。要跨这种网络,用 VPN —— Tailscale、
> WireGuard,什么都行 —— 并把网关的 VPN 地址给这些变量。

理由是:自签证书**不加验证等于没有**;自签**加钉指纹**则不能轮换、每次重装都要重新配对。
两者都付出真实代价,防的却是威胁模型里不存在的对手 —— 你自己、在你自己的网络上。在这个
模型下,诚实的答案是私有网络加一个 token,而不是对着空气上密码学。

所以 `100.64.0.5`(tailnet 地址)正是这些变量为之设计的值。公网地址需要两个开关**并且**
一个过硬的理由。

一把客户端密钥不改变这条要求,但它确实限定了泄露的代价:持有者最多花掉那把密钥的窗口所
允许的,用在它点名的模型与供应商上,而且是以那一个 Agent 的身份 —— 而不是握着能读你存下
的密钥、能改一切的管理 token。

## 端口

| 变量 | 默认 | 它命名什么 |
|---|---|---|
| `KIWANO_ADMIN_ADDR` | 不设(不监听 TCP) | 管理面的 `host:port` |
| `KIWANO_DATA_ADDR` | `127.0.0.1` | 数据面绑哪个接口 |
| `KIWANO_DATA_PORT` | `8317` | 数据面的端口 |
| `KIWANO_DAEMON_ADDR` | 不设(本机 socket) | 客户端 → 网关管理面的 `host:port` |
| `KIWANO_DAEMON_TOKEN` | 不设 | 客户端 → 那台网关的管理 token |

客户端**不需要**被告知数据端口。`/status` 会报出网关数据面所在的**地址与端口**,接管时
写进 Agent 配置的就是那一对 —— 于是你笔记本上的 Agent 最终指向的是你服务器上的网关,而
不是它自己的 loopback。

## 验证一下

在你用来管理的那台机器上:

```sh
kiwano status
```

`gateway: running` 带着远端的版本号,说明管理面可达且认证通过。然后接管一个 Agent ——
`kiwano agents takeover claude` —— 它会把那个 Agent 的配置改写成网关报出的地址,再发一个
请求。Agent 有回答,两个平面就都通了。

如果 daemon 明明在跑,`kiwano status` 却说网关不在,那是地址或 token 错了,不是网络:CLI
会说清楚它用不了的是哪一个。
