strategies

Four routing strategies, bad days included

Bind a set of candidate providers to each agent; the strategy decides who handles each request — enforced per-request by the gateway, effective immediately.

failover

Failover

Candidates ranked by priority: if the primary fails or times out, traffic moves to the next in line, and returns once it recovers.

agent
DeepSeek GLM OpenAI
roundrobin

Round robin

Weighted rotation, per session: a session keeps its provider, so the prompt cache it already paid for keeps hitting; new sessions spread across candidates by weight.

agent
DeepSeek GLM OpenAI
timewindow

Time window

Give each candidate a local time window — subscription plan overnight, pay-as-you-go by day. Windows past midnight wrap; unmatched times fall back.

DeepSeek GLM
00:00 08:00 24:00
quota

Quota cutover

Set spend or request caps per candidate; on hitting a cap traffic moves to the next, and caps reset each period — spend stays in control.

FAQ

Questions people ask before switching

The gateway, provider routing and what stays on your machine — in short answers.

What is Kiwano?+

A free, open-source, local-first AI provider manager: a desktop app plus a local API gateway that routes your coding agents' requests to any AI provider — nothing goes through the cloud. Runs on macOS, Windows and Linux.

Which coding agents does it support?+

26 today: Claude Code, Codex, Gemini CLI, Grok Build, Claude Desktop, OpenCode, OpenClaw, Cline, Aider, Continue, Crush, Droid, Goose, Pi, oh-my-pi, Hermes, WorkBuddy, CodeBuddy Code, Kimi Code CLI, Qwen Code, MiMo Code, MiniMax Code, DeepSeek Harness, Command Code, HanaAgent and ZCode. One click points each agent's base_url at the gateway; flipping the switch off restores the original config, anytime.

How does the local gateway work?+

It is one resident port at 127.0.0.1:8317 that normalizes the Anthropic and OpenAI protocols, routing and metering every request with automatic failover. Agents keep a single configuration — switching providers never touches their config files again.

Can one agent use several providers at once?+

Yes. Bind a set of candidate providers to any agent and pick a strategy: failover (priority order, automatic recovery), roundrobin, timewindow (subscription overnight, pay-as-you-go by day) or quota (spend caps per period). The gateway enforces it per request, effective immediately.

Does it track token usage and cost?+

Every request is metered into a local SQLite database: 7-day trends of requests, tokens, cost and latency, attributed per provider and agent, drillable down to a single request, with CSV export. An optional MCP server lets your agents query their own usage.

Do my API keys ever leave my machine?+

No. Keys live in a local database and are never uploaded; requests go direct from your machine to the provider — no cloud relay. The gateway only routes keys it issued itself, so a hand-edited base_url gets a 401, not a leak.

I use cc-switch — can I migrate?+

Yes, in one click. Kiwano imports your cc-switch config and brings providers and agent bindings along as-is — and adds what cc-switch does not have: the local gateway, the provider catalog and usage analytics.

Can it run headless, on a server?+

Yes. The CLI does everything the desktop app does: one command installs the client and gateway and registers the gateway as a systemd service (no root; database in ~/.kiwano), then kiwano agents takeover points your agents at it.

Is Kiwano free?+

Completely — no account, works offline. Open source under GPL-3.0-or-later.
