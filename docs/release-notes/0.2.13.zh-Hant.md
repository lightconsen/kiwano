### 新增

- **可以把 daemon 放在另一台機器上。** 用戶端現在可以指向一台不在本機的閘道 ——
  `KIWANO_DAEMON_ADDR` 給位址、`KIWANO_DAEMON_TOKEN` 給它的管理面憑證 —— app 與 CLI
  做的事都經這條連線。管理面為此加了明文 TCP 形態（部署要求見下），資料面會報出 agent
  該指向的埠：於是在第二台機器上發起的接管，寫進設定的是**那一台**的位址，而不是它
  自己的 loopback。

- **用戶端有了自己的庫。** `kiwano.db` 旁邊多一個 `local.db`，裝的是只對**這台機器**
  成立的東西：你為探測器找不到的 agent 宣告過的目錄、哪些 agent 注入過規則、以及接管
  可以撤銷所依賴的備份。首次啟動時這些列從共享檔案搬一次 —— 一次性、冪等，並且
  **不刪原件**，降級回去仍能讀到。

### 變更

- **從這一版起，Kiwano 是 Apache-2.0。** 0.1.6 起一直是 GPL-3.0-or-later。換成寬鬆
  授權是去掉重用者的 copyleft 義務，同時保留明確的專利授權 —— 這是它與 MIT 值得知道的
  兩點差別。0.2.12 及更早的版本仍是 GPL-3.0-or-later：那些已經發布，已授出的授權收不
  回來，所以分界按版本而不是按檔案。

- **app 與 CLI 都成了 daemon 的用戶端。** 讀寫都走它的管理面 API，共享庫唯一的寫入者
  是 daemon。畫面不變；變的是每一列歸誰 —— 也正因為這樣，上面那台「另一台機器」才
  成立。

- **閘道不在時，`kiwano status` 只報狀態、然後停下。** 它原本會讀本機庫，報出配了多少
  provider、綁定和用量列。可一個從自己庫裡作答的用戶端，在被指向另一台機器的那一刻答
  的就是另一台 —— 所以那份摘要沒了；區分兩種狀態的仍然是結束碼 1。

- **`kiwano providers edit` 只送你點名的欄位。** 改一個 provider 的名字，不會再順手把
  它的限額、綁定和進階設定整份重送一遍。

### 移除

- **`kiwano reload`、全域旗標 `--no-reload`、以及管理面的 `POST /reload`。** 每條寫
  路由現在自己重讀路由表 —— 寫下綁定的是哪個行程，按它路由的就是哪個行程 —— 那條命令
  已經沒有要問的事了。指令稿裡的呼叫可以直接刪掉。

### 修正

- **Provider 頁面不再承諾廠商禁止的事。** 在已用官方方案登入的 Agent 旁邊新增
  Provider 時，畫面原本寫著官方 OAuth「目前無法代理」—— 這個「目前」讀起來像一項
  待辦。它不是待辦：Anthropic 的條款（2026 年 2 月）把 Free、Pro、Max 的憑證限制在
  Claude 自家應用程式內，並明白把「代使用者路由請求」列為不允許的事。現在那句話
  直接說明原因，並指向仍然暢通的那條路 —— 用 API Key 新增 Provider。

- **`kiwano providers edit` 不再清掉 provider 的預設模型。** 這條命令沒有對應的旗標，
  而它重建的那一列總是送一個空的進去 —— 於是任何一次編輯、改任何欄位，都會把它悄悄
  抹掉。
