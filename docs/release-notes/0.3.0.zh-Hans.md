**宣告这次分离的版本。** 0.2.13 让 app 与 CLI 成了网关的客户端 —— 读写都经它的
管理面 API、共享库唯一的写入者是网关、`kiwano reload` 删掉了。那是一次破坏性变更,却
装在了一个 patch 号里;0.3.0 是把这条线画清楚的地方,跨机故事的另一半也在这里落地。

### 新增

- **数据面可以监听 loopback 之外:`KIWANO_DATA_ADDR`。** 不设就是 `127.0.0.1`,也就是今天
  每一个安装的样子,所以你不要求就什么都不变。把它设成一个私有地址,**另一台机器上**的
  Agent 就能连到这台机器上的网关 —— 这正是 0.2.13 的发布说明描述过、却没做到的事:从第二台
  机器发起的接管写下了远端那台的地址,而那台机器只在自己的 loopback 上听,于是写下去的
  地址无人应答。

- **`KIWANO_DATA_ALLOW_ANY`**,谁都能连到的地址需要它。私有网段的判据和管理面用的是同一条
  (RFC1918、loopback、链路本地,以及 tailnet 用的 `100.64/10`)。这个开关**与管理的那个
  分开**是刻意的:一个走的是凭据,而这个监听上走的是请求与响应本身;决定让前者面对网络的
  人,并没有因此决定后者也可以。

- **`/status` 在 `data_port` 之外一并报 `data_host`。** 客户端过去按自己对"网关在哪"的想法
  去拼 Agent 的 URL,只要两个平面不在同一个接口上就必然拼错 —— 而上面那个 bug 正是这样来的。

### 修复

- **从另一台机器发起的接管,现在把 Agent 指向一个会应答的地址。** 见上面的
  `KIWANO_DATA_ADDR`;这是它用户可见的那一半,接管一个 Agent 再发一个请求即可验证。

- **daemon 那行可解析的 ready 现在报的是它真正绑定的地址。** 它写着 `127.0.0.1`,因为那曾
  是唯一的可能,而在不再是之后它还在这么写。那行的意义就是被启动它的进程解析,所以报一个
  错的地址比不打印更糟。

### 变更

- **跨机配置有了一页文档:** [把网关放在另一台机器上](https://kiwano.cc/docs/zh-Hans/remote-gateway/)
  —— 两个平面、五个环境变量、管理 token 从哪儿来,以及明文传输带来的那条部署要求:私有网络
  或 VPN,绝不放在公网地址上。`kiwano` 的 CLI 参考与新页互相链接,README 也是。
